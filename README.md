# تحدّني (Tahdani)

منصة كاملة للعبة أسئلة وتحديات جماعية، مستوحاة من فكرة "سين جيم" ومبنية من الصفر بتصميم وتجربة استخدام محسّنة.

## المزايا

- تسجيل دخول برقم الهاتف عبر رمز تحقق (OTP)
- لعبة تقليدية بفريقين: اختيار فئات، لوحة أسئلة (100/200/300)، مؤقّت لكل جولة
- 5 وسائل مساعدة: اتصال بصديق، جاوب جوابين، وضحلي أكثر، الفخ، اختر المجيب
- جولة رسم وتخمين (Pictionary) بلوحة رسم كاملة (قلم/مساحة/تراجع/تقدم)
- نظام تعادل ويانصيب لتحديد الفائز
- بطولات بنظام إقصائي (أقواس) أو دوري، مع قرعة تلقائية وتتبع النتائج
- واجهة أطفال مخصصة وحقيبة طالب لمراجعة المواد الدراسية
- باقات ألعاب، مدفوعات، أكواد خصم، وإهداء الألعاب
- صفحة حلقات البرنامج التلفزيوني ونموذج التقديم للمشاركة
- لوحة تحكم إدارية كاملة لإدارة كل المحتوى أعلاه

## البنية التقنية

- **العميل (client/)**: React + TypeScript + Vite + Tailwind v4 + React Router + Zustand، بتصميم RTL كامل وخط Cairo
- **الخادم (server/)**: Node.js + Express + TypeScript + Prisma + SQLite

## التشغيل محليا

```bash
npm install

# إعداد قاعدة البيانات وتوليد البيانات التجريبية (فئات، أسئلة، باقات، إلخ)
cd server
npx prisma migrate dev
npx ts-node prisma/seed.ts
cd ..

# تشغيل الخادم (منفذ 4000)
npm run dev:server

# في نافذة طرفية أخرى: تشغيل الواجهة (منفذ 5173)
npm run dev:client
```

قبل تشغيل الخادم، انسخ `server/.env.example` إلى `server/.env` وعدّل القيم (خصوصا مفاتيح بوابة الدفع، راجع القسم أدناه):

```bash
cp server/.env.example server/.env
```

افتح `http://localhost:5173`.

حساب المشرف الافتراضي (بعد seed): رقم الهاتف `39990000` مع رمز الدولة `+973`. رمز التحقق (OTP) يظهر في استجابة الـ API مباشرة (وفي سجلات الخادم) لأن لا يوجد حساب مزود رسائل نصية حقيقي مربوط بالمشروع بعد.

## بوابة الدفع (مربوطة فعليا)

الدفع مربوط بشكل حقيقي وليس وهميا. التدفق: العميل يطلب `POST /api/payments/checkout` ← الخادم ينشئ عملية دفع حقيقية لدى البوابة ويرجع رابط دفع مستضاف ← يُحوَّل المستخدم لصفحة الدفع الآمنة للبوابة ← بعد الدفع يرجع المستخدم لصفحة `/payment/callback` في الواجهة ← تستدعي `POST /api/payments/verify/:purchaseId` الذي يتحقق من الحالة الحقيقية مباشرة من واجهة البوابة (وليس من بيانات الرجوع نفسها) قبل إضافة الرصيد أو إنشاء كود الهدية. يوجد أيضا مستقبل webhook عام (`/api/payments/webhook/:provider`) للتأكيد غير المتزامن عند النشر على دومين عام.

بوابتان مدعومتان فعليا، يتم الاختيار بينهما عبر `PAYMENT_PROVIDER` في `server/.env`:

- **Tap Payments** (`server/src/gateways/tap.ts`) — **مربوطة ومُختبرة فعليا بنجاح** ضد واجهة Tap الحقيقية (إنشاء شحنة `POST /v2/charges` والتحقق من الحالة `GET /v2/charges/:id`). ملف `.env` يحتوي حاليا على مفتاح Tap التجريبي (`sk_test_...`) المنشور علنا في توثيقهم الرسمي لأغراض الاختبار — استبدله بمفتاحك الخاص من `dashboard.tap.company` قبل الإطلاق الفعلي.
- **MyFatoorah** (`server/src/gateways/myfatoorah.ts`) — مبنية بالكامل حسب توثيق MyFatoorah الرسمي (`POST /v2/SendPayment` و `POST /v2/GetPaymentStatus`) لكن **لم تُختبر فعليا** لأن MyFatoorah لا تنشر مفتاح تجريبي عام؛ سجّل حساب تجريبي مجاني على `https://registertest.myfatoorah.com/en/` (اختر الكويت كدولة، وتجاوز خطوة البيانات البنكية) ثم ضع التوكن في `MYFATOORAH_API_KEY`.
- **Mock** — يُستخدم تلقائيا كبديل احتياطي إذا اخترت بوابة بدون تزويدها بمفتاح، حتى يبقى المشروع قابلا للتشغيل بدون أي مفتاح API.

**ملاحظة عن الـ webhook**: في التطوير المحلي (`localhost`) لا يمكن لأي بوابة خارجية الوصول لجهازك، لذلك آلية التحقق الأساسية هي `verify` عند رجوع المستخدم من صفحة الدفع (تعمل محليا بدون أي إعداد إضافي). الـ webhook يعمل تلقائيا كطبقة تأكيد إضافية فقط بعد نشر الخادم على دومين عام وضبط `SERVER_PUBLIC_URL`.

## ملاحظات حول خدمة الرسائل النصية (Mock Provider)

لا يوجد حساب مزود رسائل نصية حقيقي مربوط بعد، لذلك تم بناء `server/src/utils/sms.ts` بواجهة قابلة للاستبدال بسهولة (حاليا يطبع رمز التحقق في سجلات الخادم ويُعيده في استجابة الـ API). لربط مزود حقيقي (مثل Twilio أو أي مزود محلي) استبدل `ConsoleSmsProvider`.

## البيانات التجريبية

سكربت `server/prisma/seed.ts` يضيف: مستخدم مشرف، 4 باقات ألعاب، كود خصم `WELCOME10`، 12 فئة دائمة (بها 3 أسئلة لكل فئة بمستويات 100/200/300)، فئة موسمية لرمضان، فئة أطفال، مادتين دراسيتين لحقيبة الطالب، و3 حلقات تلفزيونية تجريبية. يمكن إضافة المزيد من المحتوى عبر لوحة التحكم `/admin`.
